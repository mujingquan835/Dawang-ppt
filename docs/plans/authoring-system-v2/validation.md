# 双样本纸面推演与开发验收

关联：[总体方案](../2026-11-04-authoring-system-v2.md)、[内部契约](contracts.md)。

状态：本文件完成的是材料到契约的纸面推演与验收设计；未生成新版样稿、未运行新版测试，不代表视觉效果通过。

## 1. 样本 A：本机五页活动提案（私有）

源材料、具体数字和照片留本机。此处只记录通用结构，不将业务素材复制进公开仓库。

| 页 | 阅读任务 | 必须保留的关系与限定 | 候选表达与关键检查 |
|---|---|---|---|
| A1 背景与目标 | 看懂为什么做、分几阶段、目标是什么 | 三阶段先后、日期区间、各阶段动作；多个目标及单位 | 阶段时间轴/分阶段表＋目标组；有目标组不能免除时间区域设计 |
| A2 直播安排 | 知道每场谁参与、负责什么 | 三角色职责、三场时间/内容/人员；一角色照片缺失，其他照片是参考 | 角色组＋排期矩阵；缺照片角色仍可识别且同组；名称增加后不裁字 |
| A3 点位路线 | 知道从哪里出发、走哪些点、怎样返回 | 四点循环、节点职责、参考时长、设备要求；图片用途为参考 | 闭环路线＋对应说明，或明确返回路径的流程；大图不能取代路线信息 |
| A4 客户接待 | 知道如何邀约、到访后谁接待 | 邀约步骤、接待顺序、客户类型→接待规则、关键跟进时限 | 邀约步骤组＋分类规则表＋接待流程；每种客户能追踪到责任规则 |
| A5 预算与预估 | 判断钱如何分配，预期产出与目标怎样对应 | 渠道金额/占比/目的、转化阶段、范围单位；预估不是承诺，目标不是实绩 | 预算比例条/表＋分阶段转化结构；不擅自用不同单位算转化率，不把无依据比例画成精确漏斗宽度 |

### A2 契约闭环推演

1. 建立角色节点、场次节点、时段事实和职责；缺照片单独记 gap，不抹去角色。
2. 分工与出场对应建立 assignment 关系，每场明确参与角色。
3. 页面任务是“谁在什么时间做什么”；拆成角色区和排期区，均绑定必需关系。
4. 角色模块共同计算图片/占位、角色和职责；排期模块按行列测量。
5. 生成后核对所有场次与角色匹配，查看最长角色名称、职责换行和无照片状态。
6. 一个区域不合格就返工该区域；走播流程带存在不能替排期区过关。

### A5 契约闭环推演

composition 关系保存渠道组成，conversion 关系保存阶段顺序及各阶段原始指标，comparison 仅用于口径可比的目标与预估。缺乏一致口径时保留阶段列表或等宽阶段图，不推导转化率。每个渠道目的仍有去向，不能只剩金额；最终复核检查可比较性和“预估”限定，而不是检查有无梯形。

纸面结论：契约可以承载五页的关键关系和素材缺口。仍需实际渲染确认混合页密度、人物长文本和范围指标可读性。

## 2. 样本 B：公开合成交接试点（另一类材料）

材料：`examples/showcase/material.md`。此为虚构示例，不代表真实业务成果。

必需事实：第 1 周 34 项任务，27 项完成，7 项待确认；待确认不是失败；拟定流程有补资料分支；确认接收后才能开始执行；一周试点分第 1—2、3—5、6—7 天；观察指标不预设改善；每页保留公开合成限定。

| 页 | 阅读任务与内容 | 关系 | 候选设计与验收 |
|---|---|---|---|
| B1 状态结论 | 看懂当前记录及其局限 | 34 的组成；完成与待确认不同状态 | 结论＋组成概览；不把待确认涂成失败，不造历史提升值 |
| B2 记录解释 | 看懂已完成与待确认怎样区分 | 状态分类、数量与单位对应 | 状态对照或简洁说明；无新数据时不为了图表补造分组；允许纯文字说明有充分层级 |
| B3 拟定处理流程 | 看懂正常路径和缺资料路径 | branch＋返回边；接收先于执行 | 条件分支流程；删掉返回边必须被检出 |
| B4 下一步试点 | 看懂一周如何安排、观察什么 | 三阶段 sequence；观察项支撑复盘 | 阶段计划＋观察项；保持计划状态，不写成已完成结果 |

推演结果：不需要人员照片、预算卡片或活动模板也能使用同一内容/设计契约；适用的是通用关系，不是 A 样本的页型组合。B1/B2 不应机械重复同一结构；实际制作若内容不足，应通过不同阅读任务组织，不能编造新事实填满四页。

## 4. 验收方法与阈值

- 内容：全部 required 项必须覆盖或有明确的用户处理决定；来源、单位、范围和状态不能错误。可选内容可精炼，记录取舍。
- 渲染：最终交付文件的关键文本无未解释裁切、遮挡、出界；视觉截图与程序报告一起判定。字号按阅读场景定，不在本轮发明一个适用于所有任务的最小值。
- 设计：逐页问“重点能否直接找到、关系能否直接读懂、图片用途是否清楚、留白是否服务阅读”。任一核心阅读任务失败则返工；纯审美偏好单列。
- 回归：比较基线与候选的事实完整性、阅读任务和实际画面，不用像素一致替代质量评价，也不以“新增更多图形”为进步。
- 效率：记录材料整理、生成、复核与返工耗时及轮次。先建立基线，再定目标；不提前承诺更快。

## 5. 负例设计原则

不能只有“正常输入成功”的测试。至少保留：内容有引用但不显示、组件存在但主要关系未表达、复核旧结论跨修订继承、第三轮仍有阻断、缺照片与长文字、主题改变导致容量变化等负例。

模型复核不能靠固定 fake-reviewer 证明质量。fake-reviewer 只验证流程和 JSON 合同；真实视觉验收必须实际运行复核并看图，最终效果由用户确认。

## 6. 本轮纸面推演的局限与待确认项

已证明：两类材料可用同一契约描述，关键关系和缺口有承载位置，开发项与验收案例可对应。

未证明：模型能否稳定完整抽取关系、真实文字容量、最终 HTML 漏检原因、不同主题下的视觉质量。后续须由 W1—W6 的实际运行验证，不能把本文件当作这些项目的 PASS。
