# 架构决策 · 0.2 开发版

材料与用途 → 叙事/逐页任务 → 关系与媒体 → 适用模板/组合 → 原dashi编辑器 → ProjectV2 → HTML与PPTX。

1. 产品代码位于`skills/dawang-ppt/project`。保留原组件、17个主题、18项本地扩展和原界面。全局原技能不改；根`runtime/`为0.1历史原型，不能作本次融合默认路径。
2. `importGoal`接收原composeDeck结果及旧HTML编辑状态。ProjectV2保留原state字段；TemplateSlide与CompositionSlide共用页面顺序、复制、跳过、删除、文字/媒体/字体状态、保存与撤销。
3. 新组合由StyleDefinition与语义对象派生；原模板继续原组件。原三套适配风格可使用相同对象；Kimi三家族分别使用证据判断、影像留白、教学图解结构。未适配旧风格不偷偷换默认风格。
4. `contentPlan`保存内容引用，`media`保存媒体引用；组/节点ID保持稳定。手工覆盖在派生几何之后应用；结构删除导致覆盖失效先返回冲突。局部改字默认建立页面独立用户编辑节点。
5. 撤销采用受影响页面/内容节点的补丁，媒体只保留引用。浏览器IndexedDB保存完整语义草稿，原编辑器原存储继续保存模板状态；二者通过统一ProjectV2合并。草稿baseRevision与磁盘不同时不自动覆盖。
6. 原子保存使用revision检查、排他锁、同目录临时文件与rename，保存旧修订。工程成功但HTML重建失败分别返回状态；导出重建已保存修订，使用同一采集与导出适配器。
7. 新产品不使用原专有导出引擎，不调用远端Kimi编辑器。独立采集文字/图片/形状/线条/SVG向量并使用PptxGenJS，图片裁切与自由形状由OOXML适配保存。表格、图表和关系图保持基础对象可编辑；PDF是独立截图格式。
8. 逻辑画布1920×1080，导出13⅓×7½英寸。原组件DOM尺寸按画布比例还原，字号除以2。字体先识别浏览器实际使用的字族，映射同字体别名；不将缺失字体名称直接交给Office猜测。
9. QA检查硬内容/图片、几何、媒体加载和revision；脚本不判定审美通过。真实图片与原编辑器截图用于本地效果样稿，公开测试采用明确标记的合成夹具。独立渲染和PowerPoint实操分别记录。
10. Kimi原文不重新分发；60份来源分别记哈希、来源版本、目的地与批次。3份首批状态为implemented-unverified，剩余57份待分批。用户视觉验收通过前不标verified、不合main、不发正式0.2.0。
