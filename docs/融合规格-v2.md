# Dawang-PPT 深度融合规格 v2

日期：2026-10-14。修订：v2.1（整合前复核）。状态：已进入0.2开发实现；效果与客户端验收见acceptance-v0.2.md，需求边界保持本规格。本文依据当前会话最新选择，替换 v1 中导致“新增少量风格＋简化渲染器”的实施解读；原规划稿保留作历史。

## 1. 已确认的目标和选择

目标：以 dashi-PPT 的制作、浏览器编辑和模板资产为产品基础，将 Kimi 的材料理解、叙事规划、关系表达、排版和图片组织逻辑融入整个制作流程，同时将 Kimi 设计库分批转为真正可制作、可编辑、可导出的模板家族。

| 决策 | 已确认选择 | 对实施的约束 |
|---|---|---|
| 融合深度 | 深度融合 | Kimi 方法实际影响页面结构，不能仅写进提示词或选页说明 |
| 编辑方式 | 结构化＋局部自由 | 保留原编辑界面；新对象支持结构编辑、位置尺寸和样式调整 |
| SmartArt | 可编辑关系图 | 使用文本、图形和连接线，不要求 PowerPoint 原生 SmartArt |
| 模板范围 | 全库分批完整适配 | 全部源规范有迁移去向；目录索引不是完成交付 |
| PPTX | 文字与图形可编辑 | 表格/图表可由文本、形状、线条表达，不要求原生数据对象 |

统一使用“Dawang-PPT”展示名、`dawang-ppt` 技能标识和现有 `Dawang-ppt` 仓库名。原 `dashiai-ppt`、`open-kimi-ppt` 全局安装保留。

## 2. 本机核查事实

- 本地 dashi skill 是指向 `Documents/PPT可编辑&AI大师/skills/dashiai-ppt` 的链接；主规则标注运行时 0.4.1，本地含 theme01–17。
- dashi 以 `layout + props` 绑定组件，已有文字/媒体/字体/属性编辑、页面排序和保存；HTML 画布为 1920×1080，编辑状态包含 text、props、typography、textFonts、mediaSlotStyles 等。
- 本地上一轮18项扩展含 theme17、元数据与通用选页相关修改；公开仓库基线没有完整纳入，必须做逐文件差异核对。
- 当前 Dawang 公开代码基线为 `2bb1c7167d125ba7ebb9a635c2427ede3b19eb27`。其独立六构图渲染器不作为本次产品主链路；可复用的台账、校验和测试思路按需提取，不能直接继承“融合已完成”的能力标签。
- 本地 Kimi 资料包含60份设计规范、44个不同路径名称、60个不同文件哈希。“44”是名称盘点结果，不是已验收模板数量；同名文本可能是不同版本，不自动合并。
- PPTD 明确提供 text/shape/line/image/icon/table/chart 元素和 bounds；没有单独 SmartArt 类型。它是开放的页面描述方式，设计决策主要由智能体按规则作出，不是可直接移植的自动排版算法。
- 当前 dashi 导出组件有专有许可，Kimi 编辑与导出依赖公共远端编辑器；两者均不作为新产品未经核验的可再分发引擎。本版保留 dashi 界面并独立实现导出适配，不据此另换制作界面。

## 3. 制作与排版的产品行为

### 3.1 统一工作流

材料和需求 → 受众/用途/场景 → 全稿叙事与逐页任务 → 关系和素材判断 → 风格/模板选择 → 页面编排 → 原编辑界面调整 → 内容/几何/视觉检查 → 导出与复核。

- 七类场景均纳入内容指导：分析决策、商业提案、管理汇报、学术研究、教育培训、技术工程、品牌创意。模板迁移可分批，场景指导不人为缩为三类。
- 输入是完整材料时先保全事实、来源、单位、时期和必需媒体；缺少业绩、目标或因果依据时不补造。
- 指定模板并要求原样时保持原结构；没有原样约束时允许在所选风格下换适配页型、调整比例或采用组合页面。不能把“深度融合”解释为擅自重排所有旧稿。
- 用户未委托且未指定风格时，沿用原风格选择体验，候选须满足硬要求。自主设计不是强制选一个 Kimi 预设。
- 新建创建独立项目；局部返工锁住未点名页面与已确认内容；整体重构须来自用户明确要求。

### 3.2 统一界面，两种兼容页面表达

原页面保持其 `layout + props` 表达；新增页面使用元素与语义组合表达。两者进入同一页列表、同一编辑器、同一保存状态和导出接口，不成为两个独立软件。

模板是一组风格和构图资源，内容规划先于页面选择。组合页面不受上一轮六种固定布局限制；它由基础元素、语义对象和风格构图规则组成。原风格也能通过新的对象组合能力表达不同内容，但不把旧组件自动转换成自由画布。

### 3.2.1 原风格接入新组合能力

保留17个原主题的模板页面；为原风格另建立 `LegacyStyleDefinition`，与新增Kimi风格消费相同的组合对象。此定义包括文字层级、字体与回退、颜色语义、网格/留白、线条/圆角、素材处理、背景和强调特征、适用密度、偏好构图；不能只抽取颜色后宣称继承原风格。

- 首批明确适配 theme13钴蓝经营风、theme09深蓝杂志风、theme16奶油蓝图风，在三种旧风格中验证新图片组、时间轴、表格及关系图。
- 原组件页面仍走原组件，不改原布局以凑自由对象；组合页面通过原风格定义绘制，使用同一个编辑器。旧主题全部可见，但尚未适配的“旧风格＋新对象”组合须标注支持状态，不能替换为默认风格。
- 原有17主题的新组合适配按批推进；对每套风格逐页记录继承和调整的理由。复杂背景/动态氛围不影响数据图含义，不把非信息装饰当成必须编辑的业务图形。

### 3.3 必须实现的排版和对象能力

| 对象 | 制作与排版行为 | 原编辑界面内的编辑行为 |
|---|---|---|
| 文字 | 标题/正文/注释层级、段落与行距、中文断行、混合语言与数字单位 | 改文案、字体字号颜色、位置尺寸、对齐；继承原全局字体和单文本字体操作 |
| 图片 | 单主图、图文分栏、主次图片组、网格、拼贴、全幅/背景、截图完整展示、形状裁切 | 替换、调整框与适配模式、裁切和焦点、图片组内排序和主次 |
| 时间轴 | 横向、纵向、交错节点；区分序列、按日期比例和阶段区间，不把时间轴当普通列表 | 节点增删排序、日期和标签、方向与分布、强调节点；连线随节点移动 |
| 表格 | 行列比例、长单元格、表头/重点行列、合并单元格、密度与边框 | 改单元格、增删行列、列宽行高、合并拆分、颜色边框字体 |
| 关系图 | 流程、层级、循环、矩阵、因果、并列比较；连接由节点 ID 表达 | 节点增删、标签、关系连接、方向、组移动缩放；子对象可单独调整 |
| 数据图表 | 优先支持条形/柱形、折线、面积、饼/环、散点、瀑布、热表、树图、层级环和桑基的可编辑图形表达 | 改数据与单位/时期、图例和强调；重新生成图形时保留可应用的局部修改 |

首批图表只要求比较条形和折线。PPTD的13种系列是后续能力清单，依后续模板家族的实际需要分批实现，不作为首批融合的前置门槛；没有用户或源模板需要的复杂系列不提前建设。各系列支持状态须登记，不能因图表不要求原生就使用整图截图替代全部内容。

“结构化＋局部自由”表示：语义对象整体可编辑，生成的子文字/图形也可调整；不建设任意复杂路径绘制、完整 PowerPoint 菜单或原生 SmartArt 引擎。组边界修改与节点移动必须保持语义连接，不留下断线。

### 3.4 排版反馈

- 元素、文本、图片和对象均能被测量；统一逻辑画布1920×1080，PPTX为13⅓×7½英寸，坐标除以144得到英寸、逻辑CSS字号除以2得到点值。PPTD 960×540几何与字号先乘2；导出测量必须在无缩放逻辑画布进行，不能直接使用编辑视口的缩放后坐标。
- 等待字体和媒体加载后测量；缺字体记录回退并重新测量。标题行数、中文标点、单元格文字与图片主体必须视觉复核。
- 内容超量依次调整可用空间、改构图、精简重复表达、在允许时拆页；固定页数/正文/图片之间冲突时报告，不删事实或无限缩字。
- 同一问题集合最多三轮智能体修正，脚本提供测量，智能体决定有意义的修正。缺陷未消除不标记完成。

## 4. 页面与编辑数据契约

### 4.1 唯一工程状态

新增 `deck-project.json`，结构为 `version:2`、requirements、sources、media、contentPlan、designChoice、slides、editorState、revision。它是新项目的可编辑工程状态；HTML 和 PPTX 都由同一最终状态产生。

- `goal.json` 保留为兼容输入；导入原 goal 与 HTML 内嵌编辑状态后建立 v2 工程。新版本不得在重渲染时仅重新读取旧 goal、丢掉浏览器修改。
- v1 状态的页面顺序、复制/删除/跳过、文字、媒体、字体和槽样式逐项映射。原文件不原地改写；不支持的字段必须列出，不能静默丢弃。
- 预览服务保存成功后原子写工程文件，再生成 HTML；导出读取保存后的同一 revision。未保存草稿不暗中当作已保存文件，保存失败/冲突时保留草稿。
- 编辑内容写回 contentPlan 对应内容节点；用户修改标为用户编辑，不伪装成源资料原文。几何和样式覆盖单独保存。

### 4.2 两种页面类型

- `TemplateSlide`：slideId、mode=`template`、layout、props、contentBindings、mediaBindings；保留旧字段契约。
- `CompositionSlide`：slideId、mode=`composition`、styleId、compositionId、objects、elements；elements 是派生的可编辑呈现对象，包含稳定 id、parentId、type、bounds、style、contentRef/mediaRef。
- `SemanticObject`：objectId、kind、data、nodeIds、relationships、bounds、overrides。对象 ID 和节点 ID 不使用数组下标；增删、排序、换图不改变其他对象 ID。
- `EditCommand`：编辑文字、替换图片、修改几何/样式、语义数据、增删节点/行列、编辑连接、移动/缩放组。每项命令进入统一撤销/重做和保存队列。
- 结构改变导致覆盖无法迁移时，返回明确冲突；应用覆盖前检查对象存在和连接完整性，不默认清空用户修改。

不要求用户手工维护这些字段。制作技能和编辑器负责生成与保存，交付突出预览、PPTX和源项目。

### 4.3 手工编辑与自动排版的明确边界

- 用户在一页直接改字，默认只修改该页绑定；若内容ID被多页复用，先建立独立的用户编辑节点，保留原sourceRef。只有明确全局修改才改变其他页。
- 改字后只测量当前文本框，默认不自动挪动其他对象；放不下时展示问题与调整候选，由用户指令或制作修正操作应用。
- 拖动、缩放、字号、裁切等手工修改保存为对象/元素覆盖，优先于自动计算。已移动的组框不因增加节点跳回初始位置。
- 增删时间轴节点、表格行列、关系图节点时，仅重排对应语义对象内部；保留存在的稳定ID及可应用的覆盖，连接跟随端点。发生遮挡或无法适配时保留草稿和冲突报告，不能以清空覆盖解决。
- 换风格默认改变风格属性，保持事实和手工覆盖；只有用户明确重新排版/清除局部调整时才解除相应几何覆盖。指定页修改不能触发全稿重生成。
- 工程JSON成功提交但HTML重建失败时，显示“内容已保存、预览更新失败”，允许重试；导出前核对工程与预览revision并重建，不能交付上一版页面。

## 5. Kimi 设计库迁入

### 5.1 范围与来源

60份源文档逐一建立稳定 sourceId、路径、哈希、别名、类别、原画幅和迁移状态。同名规范的重复部分可复用，但差异保留成版本或变体；全库完成指每份源规范都有明确去向和对应验收，不是固定承诺60套互不相同的模板。

原资料按本地路径按需读取。公开仓库发布自行编写的适配代码、规则映射、索引及来源声明；未确认许可的原文、字体、图片不直接复制再分发。

### 5.2 可交付的模板家族

每个家族应包含：视觉规范、源规范描述的页型和构图、图片处理、图表/关系图语言、密度与全稿节奏、编辑参数、兼容范围、样稿和验收记录。

源稿写明的封面/章节/正文类型按各自特点实现；没有同类源特征时不为了统一数量强造。已实现的通用对象可以复用，模板不能因此退化成相同布局换颜色。

风格库状态为 source-collected / normalized / implemented / verified；只有 verified 的组合用于正式交付，实验样稿可以显式选用 implemented。原 dashi 模板保留原能力状态，不能因进入新目录就自动标记全部验收。

### 5.3 分批顺序

1. 先验证靛蓝尽调、月白影像、蓝线课件三套命名目录版本；它们用于检验高密度分析、图片主导、教学图解三种不同构图逻辑。
2. 再处理剩余咨询/战略和工作汇报资料。
3. 然后处理财经/商业资料，再扩展学术/教育资料，最后推广/刊物类资料。
4. 每批最多五个源规范变体；批内按稳定 sourceId 排序。同名编号目录版本仍在迁移队列中，不因为首批有同名风格就跳过。

首批不是最终范围。维护一份全库迁移清单，已发布、未实现和例外来源可以逐一追踪。

## 6. 导出、兼容和公开维护

- 新产品导出适配器使用 PptxGenJS；新组合页面直接转换最终元素，旧模板由实际渲染后的 DOM/SVG 测量生成统一导出描述。
- 必需文字、数据标签、节点、表格单元格与关系图均保持文本/形状/线条编辑能力。照片仍为图片对象。仅背景、纹理和非信息装饰允许位图处理，并记录对象级降级。
- 不能把整页或关系图压成一张图片；不支持的核心对象必须阻断导出，不能默默降级。
- 保留用户看到的原导出按钮和命令入口，内部调用新适配器；不提取、逆向或改写原专有导出包，也不把原公共 Kimi 编辑器作为默认依赖。
- 图形组合表格/图表的编辑等级在能力说明中明确，不宣称原生表格、数据图表或原生 SmartArt。
- 原模板外观、新对象编辑、HTML/PPTX一致性分别回归；重点检查字体、SVG、图片裁切和坐标换算。
- Git在新开发分支工作，保留2bb1c71和原稿恢复点；分批验收后同步现有公开仓库。源码、许可和可公开测试素材入Git，个人业务材料、真实素材和生成稿留本地。

## 7. 验收与发布条件

### 必须通过的行为测试

1. 原 dashi 页面及编辑功能不退化；至少三个非 theme17 旧主题完整回归，另对 theme17 本地扩展单独核对。
2. 同一份真实材料能在原风格下使用新的图片/关系/表格表达；事实与必需内容不因换构图丢失。
3. 三套首批 Kimi 风格具有各自构图、密度和图片语言，不是元素计划相同只换颜色。
4. 时间轴2/5/9节点、长中文、横竖混合图片、8/12行长表、层级/循环图及正负零空数据能完整表达；放不下时明确冲突。
5. 实际浏览器改字、换图、节点/行列增删、组移动、子对象修改、撤销、保存重开、再导出一致。
6. “只改第三页，其余不变”保持其他页内容和布局不变；原稿来源文件仍可恢复。
7. PPTX实际检查可编辑对象；LibreOffice独立渲染；PowerPoint中代表性文字、图片与连接线实际修改、保存重开检查。
8. 用户评审代表真实样稿达到预期；未完成用户效果评审不能以代码测试替代。

### 首批范围与验收样本

**首批完整交付**：原编辑器与旧输入兼容；三种原风格的新组合支持；图文分栏、主次图片组、网格与全幅/截图完整展示；横/纵/交错时间轴；行列编辑与合并表格；流程/层级/循环/矩阵/比较关系图；条形与折线；首批三套Kimi风格。拼贴复杂裁切、额外图表系列和其余风格进入后续模板批次，不阻塞首批。

样本固定如下：

- 输入台账从现有 `output/20261013-kimi-dashi-fusion/requirements.md`、`goal.json` 和对应本地素材开始盘点；这些文件仅是可用材料候选，不把其中宣传性说明或合成数字认定为用户业绩。
- 旧版视觉基准由原运行时、原输入生成并固定为逐页截图；不能把上一轮简化新渲染器的页面当原版基准。原始字体、图片、界面和编辑操作另记录。
- 图文效果使用真实可访问图片与完整截图；原图被识别为必需证据时不可替代成蓝色矩形或图标。没有合适真实素材的样本暂缺素材，不编造业务照片。
- 时间轴2/5/9节点、8/12行表和正负零空数值使用明确标注的合成结构测试，另设一份来源可核对的真实材料综合稿。
- Kimi设计目录当前提供的是规范文档，不是本地源页面截图。每套风格先制作“规则→参数/构图→代表页”的映射表，对照规范比例、主次、密度、图片和图表语言进行复核；有可核实原页面则另附参考，没有时不声称视觉复刻官方模板。
- 首批综合样稿在三种原风格和三种Kimi风格中分别验证；内容/来源保持一致，允许在页数约束内采用该风格适合的构图。另对明确不兼容的内容返回原因，不用默认卡片结构凑满矩阵。
- 可发布条件：原样模板回归没有未解释的内容/布局/编辑退化；所有必需内容覆盖；手工调整保存重开及导出一致；核心文字/图形可编辑；逐页视觉无阻断/必修问题；用户代表样稿评审通过。评分只能是辅助，不能仅凭“像素未溢出”通过。
