# 汇报版式逻辑：从一套 245 页工作汇报模板蒸馏

排版工作汇报、述职、复盘页面时读取。来源是一套商用工作汇报模板（245 页，同一版式出 9 种配色），这里只记录它的排版**逻辑**，并已落实为排版工具与页型。不复制其图片、插画、文案、案例数字或品牌标识。与原规则冲突时按原规则；用户确认过的 Dawang 版式（数字色块、色块＋照片、深色侧栏、照片拼板）不受影响。

## 1. 一页的固定框架

- **页头：** 左上实心主色标签（如“成果数据 | 02”，标明章节与序号），标题紧跟在同一行，下方一条贯穿内容宽度的细线收住页头。页头只占画面顶部约 12%。工具：`pageHeader({ tag, title, focus })`。
- **内容区：** 细线以下到页脚之间整块使用。版面由**横向条带**（指标带、时期色带）和**等宽栏**（每栏一个对象）两种骨架组合，很少自由散排。
- **页脚：** 细线之下只放来源与页码，字小、颜色弱。来源只写材料名称和时期，不写定稿、版本、字体规范。
- **进度：** 页头细线上的主色粗段按页序变长（用户调整：放在标题下方），兼作标题区的分隔。

## 2. 颜色职责：一深一浅一跳

9 种配色共用同一结构：白底、近黑正文，加三种颜色。统计全部页面的颜色引用，主色约占 60%，辅色约 10%，跳色约 3%，其余是白色与中性色。

| 职责 | 用在哪里 | 语义 |
|---|---|---|
| 主色（深） | 页头标签、实心锚定块、本期数字、左侧/已达成一侧、主时期 | 本期、已达成、结论 |
| 辅色（浅） | 对照一侧、上期数据、未达标进度条、交替时期 | 上期、差距、待改进、计划 |
| 跳色（艳） | 整页只给一处：最强的一项、排名第一、关键目标 | 唯一的最高点 |
| 浅主色底 | 指标带、对照一侧的底面（主色约 6% 浓度） | 成组，不加描边 |

做法：先按语义分配主辅色（本期/上期、亮点/待改进），再决定跳色给谁；跳色出现两处以上就失去作用。工具：`colorRoles(palette)` 返回 primary / secondary / pop / band / soft；没有这些键的旧配色自动回退为 ink / accent 浅色 / accent。

九组配色见 `project/src/fusion/authoring/report-palettes.mjs`（`reportPalette('blue-gold')` 或中文名），可作为配色候选交给 `palette-preview`：

## 3. 反复出现的五种结构

模板七类页面（数据、逻辑、排期、流程、框架、图文、封面目录章节）几乎都由下面五种结构组合而成。

**① 锚定块：** 每页有一个实心主色块装“答案”（整体完成度 94.5%、年度合计、2025 计划目标），其余指标排在它右侧的浅色带上，用细竖线分隔。读者第一眼落在锚定块，再横向扫读。工具：`kpiStrip({ anchor, items })`；单独一块答案（数字或短语）用 `answerBlock`。

**② 同列对应：** 目标、实际、完成率、说明落在同一栏，从上到下读完一个指标；栏与栏之间不混。只有真的逐项对应才这样排。页型：`targetVsActual`；页面里只有一组目标对实际或前后对照时用组件 `comparePair`。

**③ 镜像对照：** 两侧同构、逐行成对（今年/去年、亮点/待改进、问题/改进、挑战/方案、项目 A/B）。左侧主色、右侧浅辅色，中间一列编号 01/02/03 把每一对连起来，VS 圆标压在分界处。两侧条数可以不同，逐行成对时用整页 `contrastColumns`，只需一块区域时用组件 `contrastPair`。

**④ 时期色带：** 顶部一条箭头色带按月/季度/阶段分段，主辅色交替，每段正下方一栏写该期重点、达成率和要点；底部再用一条锚定指标带汇总全期。页型：`periodColumns`。甘特图、周计划等排期页同理：时间是横轴，任务是行。只要色带、下方内容自定时用组件 `periodBand`。

**⑤ 等宽栏中的一栏反白：** 3–5 个并列事项用等宽栏，每栏顶部一条色帽或标签；需要突出其中一项时，整栏改为主色实底、白字（其余保持浅底），不靠放大。用 `metricTiles` 的 `highlight` 加 `highlightStyle:'solid'`。

## 4. 七类页面对应的汇报角色

下表说明模板各类页面借鉴了什么；每页实际用哪个页型或组件，以 `outline:check` 的 `suggestions` 为准（选择逻辑只在代码里维护一份）。

| 模板类别 | 页数 | 对应大纲 role | 主要借鉴 | 先用的工具 |
|---|---|---|---|---|
| 数据类 | 53 | results / summary | 锚定块＋指标带；今年/去年左右分色；目标—实际两行对照 | `targetVsActual`、`kpiStrip`、`metricTiles` |
| 逻辑类 | 76 | issues / causes / summary | 亮点 vs 待改进；问题→原因→改进逐行；PDCA、SMART、SWOT 等复盘模型 | `contrastColumns`、`flow`、`numberedList` |
| 排期类 | 16 | plan | 月份表头＋任务条；季度目标＋周计划 | `periodColumns`、`table` |
| 流程类 | 26 | actions / plan | 时间轴分段；阶段成果＋完成率；职业成长阶梯 | `periodColumns`、`flow` |
| 框架类 | 32 | actions / duties | 目标拆解、组织架构、OKR 分栏、挑战与方案 | `numberedList`、`tableWithPanel`、自由组合 |
| 图文类 | 10 | resources / duties | 图片带＋阶段说明；个人履历；荣誉墙 | `listWithPhotos`、`imageFill` |
| 封面目录章节 | 20 | 封面、目录、过渡 | 大号章节编号 01/02；深色满版章节页；目录横排编号栏 | 自由组合 |

述职常用顺序可参考模板目录：工作概述 → 成果亮点 → 业绩分析 → 不足改进 → 成长收获 → 未来规划，与大纲的 duties / results / issues / plan 对应。

## 5. 数字与文字的排版

- 数字与单位同一文字元素，单位约为数字 40%；同一行指标同字号同基线。
- 目标行：指标名在上、数值在下；实际行：数值在上、说明（达成目标 114%）在下，两行列位置一致。
- 未达标在辅色、达标在主色，完成率用细进度条表达比例（分母是目标），超过 100% 时条满格、数字照实写。
- 要点用小圆点和悬挂缩进，换行后文字对齐文字而不是对齐圆点；要点字号 22–28px，随版面空余自动放大。
- 行与行之间用细线分隔，成组用浅色底而不是描边卡片。

## 6. 不借鉴的部分

- 3D 立体图形、拼图、立方体、金字塔透视、卡通人物与奖杯插画：装饰性强，与原规则“无意义装饰”冲突，也无法可编辑地复现。
- 模板里的图表多为占位数据；本引擎不支持原生图表，不要为了像模板而编造柱状图。确有数据时用指标、进度条、表格表达。
- 9–12px 的密集小字、满页虚线框：投影场景读不清。
- 每页都放 VS 圆标或箭头色带：结构要按内容选择，同一结构连续出现会触发 `visual-layout-repeated`。

## 7. 使用方式：拆成组件，默认使用

模板里的数字都是占位，学的是关系，不是数字。这些结构不要求材料“对得上”某个页型：按页面角色和内容关系（结论、目标与实际、前后对照、问题与改进、时间推进），在页面的某一块区域放对应组件。数字有没有、有几个、是数字还是一句话都不影响使用。

| 组件 | 承载的关系 | 默认用在 |
|---|---|---|
| `answerBlock` | 一块实心主色装本页答案（数字或短语都可以） | 整体结论、职责定位、下一阶段核心目标 |
| `comparePair` | 目标 → 实际、之前 → 之后、去年 → 今年 | 结论页、成果页里任何一组前后/目标对照 |
| `contrastPair` | 现状/问题 vs 改进、问题 vs 原因、亮点 vs 待改进；两侧条数可以不同 | 问题差距、原因复盘 |
| `periodBand` | 按月/季度/阶段分段的箭头色带，下方每段放内容 | 关键动作、下一步，凡有时间推进 |
| `kpiStrip` | 实心块装整体数字，同级指标并排 | 成果页的指标行 |
| `metricTiles` + `highlightStyle:'solid'` | 并列几项里只把最关键的一项整块反白 | 并列动作、并列指标 |
| `sidePanel` | 深色侧栏：关键数字＋编号事项 | 需审批/支持事项 |

`outline:check` 的 `suggestions[].components` 按页面角色和关系词（目标、去年、同比、季度、阶段……）给出默认组件；整页页型（`targetVsActual`、`contrastColumns`、`periodColumns`）只是这些组件排满一页的现成组合，内容不完全匹配时直接用组件自己组合。汇报稿里自由组合的页面（`visualDecision.pattern` 以 `free` 开头）至少用一个组件，否则 `make` 以 `report-component-missing` 拦下；封面、目录、章节页写 `waived`，用户决定不用的写进 `requirements.userDecisions`。

选配色时可把九组配色之一作为候选（经 `palette-preview` 展示给用户），选定后以 `createTheme({ palette: reportPalette(id) })` 建主题；其他配色也会按一深一浅一跳自动分配组件颜色。示例见 `examples/report-patterns.mjs`（第 4 页为组件自由组合）。

## 8. 把重点提出来：标签模块

读者只看标题、标签和加粗就能说出本页逻辑。`labelBand` 放一句话模块（色条＋标签＋一句话，暖色只给复盘判断），`actionPanel` 放编号动作（概括小标题＋短标签＋完整句），模块按问题、动作、结果、判断的顺序堆叠。默认由 `composeReportDeck` 生成，写法见 `examples/report-modules.mjs`。
