# 文案编辑：在制作中主动改善表达

用于新建、重构和文案优化。目标是让观众更容易理解、记住、判断或行动；“更有吸引力”随受众和用途变化，不以金句数量或措辞夸张程度衡量。

## 编辑范围

- **新建或重构：** 默认可以重写标题、提炼主张、合并重复内容、调整说明顺序、解释材料支持的使用意义、补充有依据的承接和收束。用户提供材料不等于要求逐字照搬；已确认的主线、固定页数和必需信息仍保留。
- **局部文案优化：** 在指定段落或页面内改进，保留其余已确认内容。
- **仅改排版、原样复刻或明确“文案不变”：** 保留原文；发现表达问题可单独指出，不自行套用全文改写。

事实、数值、单位、时期、对象、状态、条件及因果含义保持准确。表达改写不授权新增业绩、案例、用户评价、竞品缺点或效果保证。缺证据时写清未知或建议，不用更强的语气替代证据。

## 排版前：先完成可上屏的文案

结合已有材料确定受众关心的问题、当前理解程度和看完应有的判断或行动。用途足够明确时直接执行；不能合理判断且会改变核心表达时才澄清。内部只需简短记录本次表达目标，例如“让第一次接触产品的人理解它省去哪一步操作”，不要求额外表单。

阅读时分清事实与证据、已有强表达、需要解释的概念，以及重复或缺乏支撑的表述。原句准确有力时保留；材料只是功能、过程或零散记录时，主动组织出能承载重点的句子。

按实际问题选择编辑动作，不必每页逐项执行：

| 原稿问题 | 可采用的编辑动作 | 判断依据 |
|---|---|---|
| 标题只报主题，如“项目进展” | 提炼材料已支持的主要进展、阻碍或判断 | 标题是否让受众更快理解本页重点；目录和分类标题可以保留 |
| 只有功能或技术参数 | 连接使用场景、减少的操作或可感知变化，机制放到支撑层 | 用户意义是否可由事实推出，是否扩大效果 |
| 过程记录很多，结论不清 | 围绕读者问题重组，区分结果、原因、尚待验证和下一步 | 不把先后发生写成因果，不把投入写成成果 |
| 句子抽象、术语密集 | 换成具体对象与动作；专业受众需要的术语保留并解释 | 是否更容易理解，同时保持技术含义 |
| 每项内容同等强调 | 选出影响理解或决策的重点，其余作为解释、证据或补充 | 删除辅助信息后主张是否仍成立，重要条件是否仍可见 |
| 文字完整但难以记住 | 用简洁、具体的句子概括核心意思，必要时首尾呼应 | 能否复述实际价值，而非只记住一个口号 |

难以确定的核心标题或定位句，可以比较少量不同表达角度：结论、使用场景、用户收益或动作。选择最符合本次读者任务的一句，而非固定生成多个版本让用户挑。普通说明不必逐句生成候选。好句子可以保持不变。

形成可直接用于页面的标题、重点句和说明，放入现有短提纲或工程；不要把“待润色”留给排版阶段，也不要只写“请增强吸引力”就继续绘制。重要改写简短记录依据或删并理由，无需输出长篇思考过程。

## 按场景调整表达力度

同一事实面对不同受众，可以采用不同措辞。以下为说明方法的合成示例，不是必须使用的模板：

**来源事实：多人同时修改同一条记录时，系统拒绝过期版本的保存并提示冲突。**

- 面向使用者：**同时修改有冲突，先确认再保存。** 说明：系统会提示版本冲突，避免旧版本覆盖其他人的修改。
- 面向技术评审：**拒绝过期版本写入，冲突需显式处理。** 说明：保留版本检查机制，并说明重试或人工处理的实际支持范围。

产品介绍侧重具体使用价值；经营汇报侧重有证据的判断和下一步；技术评审侧重机制、取舍和边界；培训侧重动作与条件。形式不必固定，不要求所有页都有营销金句、反问、对仗或“问题—方案—结果”。

## 成稿后：从读者角度再检查一次

按 [内容表达复核](visual-review.md#内容表达复核) 查看实际页面，重点比较改写前后：主张是否更明确，措辞是否更具体，读者是否更容易理解或行动，证据含义是否保持。若只是换了同义词、加了形容词或把句子缩短，却没有改善上述任一项，回到具体问题调整；没有改进空间时保留原句。

这一轮可以改动重点句、阅读顺序和强调方式，再做必要的排版复核。没有新问题就结束，不为了“精修”反复重写已成立的内容。这里只是当前制作模型的第二遍检查，不宣称独立审稿或客观评分；实际效果由成稿及用户反馈判断。
