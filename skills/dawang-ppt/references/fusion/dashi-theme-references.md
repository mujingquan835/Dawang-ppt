## 在原制作流程中使用

按本次主题、受众、语气、数据密度和图片需求，从完整库定位值得研究的方向。选择数量由实际需要决定。场景定位是检索提示，不是主题适用范围的硬限制；旧 `styles` / `styles:grid` 的有限适配外观也不代表全部参考范围。

定位后实际看相关主题页面：正文、图文、数据或关系页优先与本次内容对应，封面只能说明部分视觉语言。原样模板研究可沿用 `render:goal` 的独立临时工程，使用实际存在的layout；通过 `npm --prefix <skill>/project run layout:query -- --theme <themeId> --limit 3` 查询候选，需要字段细节时再用既有 `inspect:layout`。临时原版研究与用户成稿分开，默认文案、品牌、案例与数字不进入用户稿。

确需取色时核对对应页面和主题源码的实际定义；主题内部可能有多组配色和深浅变体，不把每个主题压成唯一的五色表。颜色职责及迁移方法由[配色参考](palette-cases.md#迁移到当前页面)维护。

例如从炫光或霓虹页面可研究高彩度强调与暗背景的配合，从经营或调研页可研究数据与文字的颜色分工，从产品发布或影像页可研究大色面和真实图片的衔接；最终判断以所看的具体页面为准。不同主题中的方法可转译到本次已确定的视觉语言中，保持全稿一致，避免逐页照搬互相冲突的完整外观。

## 来源定位

本skill内置 `project/src/components/themes/theme-catalog.js` 汇总主题元数据，`project/src/components/themes/` 与运行时资源保留实际页面实现。优先使用当前skill自带来源，避免依赖另一台电脑不存在的外部安装路径；具体来源和实际渲染结果需要分别核对。
