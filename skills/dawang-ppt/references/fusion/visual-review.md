# 视觉评审与交付验收

先看全稿节奏，再逐页检查读者任务、结论、证据、关系、字体层级、图片主体和密度。按实际读取的原规则与用户材料复核；原样模板对照原截图，不把自主设计称为官方复刻。

## 内容表达复核

对照原材料和逐页短提纲，看实际页面，而非只检查文件里是否出现关键词：

- 连读标题与结论，能否理解全稿主线、各页作用及推进关系？不强制所有标题都写成结论句，但不能靠口号掩盖内容空缺。
- 主要观点是否有相应的事实、机制或例子？技术细节是否解释了受众需要理解的意义？图注、截图或随包原文是否成了某项主要价值的唯一承载？
- 图片取景与重绘是否保留关键内容和关系？图能证明什么、不能证明什么，是否与正文主张相符？
- 精简后是否丢掉关键分支、使用条件、异常行为或待核状态？辅助内容是否合理归并，而不是因字多一律删除？

发现问题先调整内容取舍和论证，再排版；不靠增加泛化形容词、堆更多功能或缩字填补。记录重要删并及理由即可，不要求输出完整思考过程。程序coverage为空、关键词齐全、零几何错误均不能证明内容表达充分；用户实际评审另记。

## 布局与工程复核

QA与导出共用readiness：字体/图片完成、有效且稳定尺寸、有限测量值、导航就绪。零scale、坏图、新制作缺字体或不支持的信息内容明确报告，不靠固定屏幕宽度或假等待绕过。旧工程的字体回退警告与新制作严格字体检查分别记录。

检查全部必需事实/媒体、文字溢出和重叠，在浏览器实际查看全稿和可疑页，或查看1920×1080临时截图；默认不写出永久截图或总览，只有显式 --screenshots 才保留。先调整空间、层级与构图；超量则提出拆页或精简重复表达选项，不删必需事实或无限缩字。同一问题最多三轮有依据的修正，仍未解决时提供证据与选项。

| 层次 | 必须记录 |
|---|---|
| 程序检查 | readiness、finiteBounds、coverage、浏览器异常、不支持项 |
| 内容判断 | 对照原稿与逐页提纲，核对主线、主要价值分支、事实/机制与使用意义、证据、删并理由、数据口径和状态限制 |
| 看图检查 | 全稿节奏、逐页构图、截图可读性、取景、修正轮数 |
| 编辑回环 | 改字/强调、位置或换图、撤销重做、保存重开 |
| 默认交付 | 仅一个HTML，全稿检查、离线编辑/下载保存与快照一致；其他格式用户按需导出 |
| 版本验收 | 完整编辑/导出回归，LibreOffice独立渲染、PowerPoint打开/编辑/保存重开分别列证据；单稿不重复整套引擎回归 |
| 用户认可 | 只记录用户实际给出的意见；代码通过、继续开发不自动等于视觉认可 |
