# 视觉设计方法

新建或视觉重构时，在上屏文案成立后、元素排布前读取本文件。局部标题修改只执行相关部分，保留正文、图片与人工位置。用户指定的品牌、视觉方向与锁定文案优先；继续执行适用的 Kimi 原始规则。

## 先确定视觉任务

先根据本页读者任务、主张与证据确定信息关系，再在现有逐页短提纲中简短记下主视觉、主张与支持内容的空间关系、字体职责、颜色分工和阅读顺序；全稿再看密度与明暗的推进。由制作智能体完成，不增加用户必填表单、工程字段或固定页序。

标题强调、字体搭配、面积对比与图文对应是可迁移的方法；某次认可的宋体、暖铜色、深色背景或三页组合仅属于当次实现。同一信息关系可有多种构图，数据、图片、文字的实际信息量决定取舍。已有品牌、受众需要与用户确认方向继续优先。

## 参考资料的职责与边界

自主制作沿用SKILL中的材料理解、原规则阅读、内容策划、自主设计、编辑保存、复核与单HTML交付。配色交互统一由[配色推荐与确认](palette-selection.md)维护：尚未指定且未委托的新建或视觉重构需展示预览并等待选择，可与大纲确认合并。配色和版式参考在现有设计阶段按需使用，决定记录在原逐页提纲，不增加必填工程字段。

| 内容 | 维护位置 | 使用范围 |
|---|---|---|
| 内容取舍、事实与证据完整性 | 制作规则与文案编辑 | 先形成成立的上屏内容；案例不改变必需内容、条件或媒体要求 |
| 视觉判断与本次取舍 | 本文件 | 确定层级、颜色职责、空间关系和全稿一致性 |
| 配色询问、预览与用户选择 | 配色推荐与确认 | 按条件确认一次，选定后沿用 |
| 颜色职责与补充色值 | 配色参考 | 需要配色依据时查阅，保持参考范围开放 |
| 原版主题发现与研究操作 | dashi主题索引 | 定位当前完整库与具体页面，不把原版模板流程带入自主制作 |
| 空间关系与案例说明 | 版式案例 | 根据当前信息关系借鉴，可自主重组 |
| 草图与索引展示 | 离线案例页 | 辅助理解，不另行规定制作规则或作为成稿验收依据 |

先遵守本次编辑范围、锁定内容、品牌及已确认方向；在这些条件内采用适合的参考。原版配色与品牌冲突时转译其强调、面积或明暗关系，保留本次品牌含义。版式容量或视觉效果与必需内容冲突时，调整构图和区域分配，按原制作规则处理拆页或精简；不为了适配参考省略事实、条件、表格或图片。

局部修改只作用于授权元素。旧工程若缺少内容引用，沿用已有上屏文字补齐内部引用，不借字段补全重写页面或移动锁定内容。

已确认方向可直接沿用；只改标题或局部配色时读取对应方法即可。新建或视觉重构需要新依据时，再查有关案例和原版页面，已在本会话看过且仍适用的参照可复用。多个来源最终归入同一稿件的颜色、字体和层级职责，页面可按内容变化，保留同一状态或数据类别的含义。

参考页的主题编号、配色和版式不会自动将任务切换为原样模板。配色确认按上述交互规则执行，不引入原版模板九宫格门禁。Kimi原文的读取条件继续由主流程决定，设计系统仍仅在用户指定时读取。用户明确要求原样模板时才走已有兼容入口；自主制作继续使用原有authored工程、make / publish:html及QA。

## 标题内部的关键词设计

先找最值得记住的动作、价值或结论，再选择强调方式。引导语与重点词分别承担阅读职责，强调范围按语义确定。

| 表达需要 | 可选处理 | 实际复核 |
|---|---|---|
| 让关键意思先进入视线 | 重点词变色，其他部分维持主要文字色 | 去掉颜色后仍能读懂完整标题；颜色突出的是核心意思 |
| 增强力量或分清主次 | 对比字重、字号、字宽与疏密 | 重点与引导语有差异，读者能顺畅读完整句 |
| 表达个性、情绪或品牌气质 | 对关键词使用适合主题的艺术字体 | 中文字符完整、字形易辨、实际字体加载；离线与目标环境的可用性有依据 |
| 长标题或多层语义 | 按意群断行与调整位置 | 关键词和必要条件不被割裂，没有孤立标点或因缩字损失层级 |

例如“选定拍摄对象，让画面跟随主体”可先弱化引导语，再重点处理“跟随主体”；另一份内容应重新判断语义重点。并非所有标题都需要多种字体、颜色或极粗字重。正式汇报、技术评审同样可以强调，但力度与受众匹配。

实现时用同一文字元素的 runs 保留分段颜色、字体、字号和字重；确有独立构图需要时可分成多个文字元素。主标题的强调不要让辅助标签争夺第一层级。编辑后检查断行与整体文本框高度；保存重开后核对分段样式。

已认可的标题方向直接沿用。只有实际改动、长标题、缺字、字体回退或保存异常等新情况才做针对性检查，不把每次任务都变成重新比较标题方案。

## 让颜色参与构图

先确定背景、主要文字、强调、辅助信息与结构面的颜色职责；深浅背景可分别使用适合的文字和强调色。颜色选择由主题、产品视觉、品牌要求与受众决定，不固定为白底黑灰字加小标签，也不把某次认可的黑金方案作为所有项目默认值。

强调色可以用于标题关键词、核心动作、关键关系或有意义的结构面。决定面积、位置和对比，避免全稿仅在小序号处着色。按内容需要调整各页明暗和密度，保持同一视觉语言；不要求固定深浅页序、色数或面积比例。表格与图表的颜色还应保留数据分类和状态含义。

需要具体配色参照时按需读[配色参考](palette-cases.md)，可从dashi完整主题库、按主流程已读取的规则或当前素材寻找方向，再借鉴颜色职责和面积关系；文档中的补充示例不限定可用配色。

## 用户未提供图片时

“用户没有上传图片”时，先盘点项目中已授权的真实素材，再判断本页需要哪种视觉信息：

| 本页任务 | 制作动作 |
|---|---|
| 展示真实对象、界面或证据 | 选取对应原图或清晰局部，保留必要上下文；缺失的证据明确记录 |
| 解释步骤、组成、依赖或取舍 | 依据已有事实，用可编辑文字、线条、形状构成关系示意 |
| 建立场景或概念氛围 | 按已有授权搜索或生成合适图片，区分真实素材与概念图 |
| 观点本身承担表达 | 用文字层级、位置、留白与主题图形完成构图 |

真实证据、说明示意与装饰氛围分别处理。生成图和示意图不能成为实测结果、真实案例或产品界面的替身。判断已有授权后继续可执行的工作；补图授权不等于扩写业务事实。

## 图片与说明共同组织

先确定图片具体支持哪句说明，再决定整图、局部或组图；解释靠近对应区域，文字和图片共同完成表达。完整截图用于认清对象与上下文，关键局部用于看清操作、细节或证据。整图缩小后关键文字不可读时，可采用局部放大或调整图文面积；需要观众直接理解的动作与结论由可编辑正文表达。

界面总览与关键局部承担不同任务时可有目的复用同一原图，并清楚标出对应关系。局部保留识别对象、理解条件所需的标签与上下文；历史界面、合成示例等状态在相关说明附近表达。构图参考中的装饰图片与当前证据用途不同，应重新选图或改用其他关系表达。

取景前核对源图尺寸、主体位置与组图的实际拼接边界。裁切后检查源区域与展示框的比例、关键文字完整性、主体位置及相邻画面是否混入；采用可编辑裁切时保留原图。看图时同时核对全页关系和关键局部的实际可读性。缺少同片段、对齐或参数信息的静态组图，只按其可支持的场景或说明用途呈现。

## 少字页的构图

少字页也要有第一视觉落点和下一步阅读方向。单一主张可由标题形成主视觉；流程可以突出关键步骤，其余步骤辅助；对比可通过空间和比例建立关系。图形语言可来自主题中的实际对象或操作，如框选角标、路径或范围边界，含义要清楚，不能暗示未测得的数值或轨迹。布局随信息关系变化，不把同样的左右分栏、卡片或等分方式套到每页。

## 使用视觉案例

用户要求参考 dashi 或需要具体构图依据时，按本页信息关系读取[版式案例](layout-cases.md)，实际看相关页面，再提取适用关系。案例负责说明参照如何工作，具体排版仍由当前内容决定；不按案例编号自动选页，不把一组案例固定串成整稿。配色案例与版式案例可分别借鉴、重新组合。

现有案例不适合本页证据时，继续依适用的 Kimi 场景规则自主设计，例如按数据口径组织图表与表格，按真实图片取景组织图文。明确要求原样大师模板时，使用既有兼容入口。
