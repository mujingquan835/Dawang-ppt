# Dawang-PPT

制作和编辑基座是原 dashi 操作台。旧模板保留 layout+props，新组合页进入同一目录、画布、侧栏、撤销和保存队列。PowerPoint 用于交付后的编辑与验证，不能替代网页制作入口。历史六构图 runtime 只作恢复资料。

## 入口与制作

先执行 `node <skill>/scripts/dawang.mjs doctor`。运行时随技能目录维护；首次使用在仓库执行 `npm ci --prefix skills/dawang-ppt/project`。不运行原技能自动更新器覆盖本产品，不改原全局 dashiai-ppt/open-kimi-ppt 安装。

1. 区分新建、局部修改、整体重构、指定原样模板。读取完整材料，记录受众、用途、页数、单位、时期、来源与必需照片。按 [制作规则](references/fusion/production.md) 与对应的 [场景规则](references/fusion/scenarios.md) 规划，不补造结果、目标或因果。
2. 先明确全稿叙事、逐页读者任务、结论和信息关系，再选择适用构图。原样要求使用原组件；新组合按关系选择时间轴、表格、关系图、条形/折线及图片组合，保留必需内容引用。
3. 用 `styles` 查看统一候选库。17个原主题保留模板能力；theme13/09/16已接入组合对象。首批Kimi为靛蓝尽调、月白影像、蓝线课件，当前是 implemented、待用户视觉验收。其余来源清单不等于可用模板。沿用用户已确认风格，兼容性冲突时给证据和选项。
4. 新稿使用模板字体；导入旧稿保留字体设置。全局字体控件供用户主动统一。照片与文字截图分开：截图完整 contain；月白多张必需照片拆页，固定页数冲突先询问。靛蓝允许已确认的照片证据扩展。
5. 按 [工程与命令](references/contracts.md) 构建，打开原编辑器，提供预览和源项目。用户无需手写JSON。局部返工锁住未点名页面，使用稳定ID；手工几何和样式优先，结构修改使覆盖失效时先报告，不能清空覆盖。
6. 按 [视觉复核](references/fusion/visual-review.md) 检查：字体和媒体加载、全部内容、溢出重叠、主体与截图完整性、逐页节奏，再检查PPTX对象和独立渲染。几何通过不是审美通过。同一问题最多三轮有依据的修正；不可无限缩字或删字段。
7. 交付原编辑器预览、可编辑PPTX、完整源目录和实际验收状态。表格/图表/关系图由文字、形状、线条组成；不承诺原生数据图表/SmartArt、任意PPTX导入或所有客户端像素一致。

## 保存与冲突

唯一工程为 `deck-project.json`（ProjectV2）；HTML与PPTX读取同一已保存revision。重渲染用 `render:project`，不能重新导入初始goal覆盖编辑。浏览器另保留完整本地草稿；磁盘修订冲突时保留两份并报告。源工程写入成功但预览失败要分别说明，不交付旧预览冒充新稿。

详细能力与未验收项见仓库 `docs/acceptance-v0.2.md`；来源、画幅适配与后续批次见 `docs/style-migration-v2.json`。正式效果验收通过前不合入main、不发布0.2.0正式版。
