# Dawang-PPT

先区分新建、指定源项目的局部修改、导入重建；再区分自主设计、指定风格、沿用模板、参考风格迁移。用户明确调用其他技能时尊重选择。

## 工作入口

本技能与项目运行时一起安装。脚本 `scripts/dawang.mjs` 从技能目录定位仓库；先运行 `node scripts/dawang.mjs doctor`。首次运行需在仓库执行 `npm ci`。不要运行旧技能的自动更新器来覆盖 Dawang。

1. 读取原始材料，建立本次独立项目目录，记录受众、目的、用途、正文页数、封面、图片、表格和最终格式要求。
2. 只读取对应的 [场景规则](references/scenarios.md)。用户事实进入 sources 台账，真实图片进入 media 台账；缺失数值不写成零，外部资料不冒充个人业绩。概念图不能冒充业务证据。
3. 按 [数据契约与命令](references/contracts.md) 形成内容计划。页面先明确读者任务和关系，再选择构图。必须内容使用稳定 ID，不因模板容量静默删减。
4. 用户指定或已确认风格，核对兼容性后沿用；明确委托则记录选择理由后继续。尚未指定也未委托时，展示少量适配方向并等待选择。三套内置风格是实验适配；源风格索引的“已收录”不表示已能生成。
5. 新构图使用统一内容驱动路径；指定旧主题读 [兼容与返工](references/legacy-and-revision.md)。自主设计将规则写入 design-brief 参数。任意 PPTX 模板导入、参考图自动迁移、原生数据图表和 SmartArt 尚未支持，不承诺无损重建。
6. 构建 → 字体图片加载后几何 QA → 整稿和逐页视觉复核 → PPTX 导出 → 独立渲染复核。读 [验收边界](references/quality.md)。同一问题集合最多三轮修正。不能无限缩字、隐藏溢出或挪入备注来假装满足硬要求。
7. 默认交付 PPTX 与完整本地 HTML 源项目。源项目包括全部台账、输入、媒体、渲染计划与编辑状态。PDF 按需。给出实际证据和未完成验收；不能仅凭脚本通过声称视觉通过。

## 局部修改

“其余不变”锁定未点名页面、内容与已确认风格。先保存快照，再按稳定内容或对象 ID 修改。浏览器的“保存修改”回流 sources/media 和 edit-state；冲突时保留草稿并报告。重新构建和导出使用同一份状态。只换风格时保持 content-plan 和 sources 不变；覆盖对象失效必须明确报告。

## 能力状态

已实现：三场景规则，六类构图，三种风格参数，自主参数风格，浏览器文字/图片及局部位置编辑，本地原生文本/图片/形状/连接线/表格导出。

能力是否已验证，以项目 `docs/acceptance.md` 及对应版本报告为准。风格仍需用户效果评审；Office/WPS 的跨客户端一致性不默认承诺。完整风格库、模板解析和自动参考迁移属于后续工作。
